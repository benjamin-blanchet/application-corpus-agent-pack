# Schemas

Lightweight schema specs for the central `doc/_meta/*.yaml` files written by
pack skills.

## Why this exists

Two corpora generated by the same pack on different applications must produce
**iso-shape** outputs — same field names, same nesting, same vocabularies —
even when the content (number of features, criticality counts, etc.) legitimately
differs. The SKILL.md files describe schemas in prose, which a generating LLM
will riff on across kickstarts. These files are the single source of truth that
`scripts/validate-corpus.mjs` lints against.

## Format

Not JSON Schema — too heavy for our scope. A small home-grown YAML format,
purpose-built for what actually drifts in real corpora (field-name aliases,
enum drift, missing required keys, free-text creep).

```yaml
# Top-level metadata
file: doc/_meta/<target>.yaml          # path relative to corpus root
description: |
  One-paragraph what this file is for and who writes it.
written_by_skill: <category>/<skill>   # source of truth in SKILL.md

# When the target file is a list of homogeneous items (e.g. bricks,
# contradictions), declare the item shape under `item:`. Lints apply to each
# item inside the list block.
item:
  inside_block: bricks                 # only lint lines under this top-level key
  required_keys: [id, kind, label, ...]
  optional_keys: [actionability, cross_refs, ...]
  forbidden_aliases:                   # map of legacy field name → canonical
    type: kind
    priority: criticality
    title: label
  enums:                               # closed value vocabularies
    kind: [feature, api, ...]
    criticality: [critical, high, medium, low]
```

## Adding a new schema

1. Create `<file-basename>.schema.yaml` here.
2. The linter auto-discovers schemas in this folder at startup.
3. Findings are emitted at P2 (warn) by default. Promote to P1 only after at
   least one full kickstart cycle confirms operators do not produce false
   positives.

## Migration scaffold

- [corpus-state.yaml.template](corpus-state.yaml.template) — canonical fallback
  copied by `governance/pack-upgrade` only when an older corpus has no state
  file. The release tests require it to remain byte-for-byte identical to the
  fresh-install model at `doc/_meta/corpus-state.yaml`.
