# Corpus Generation Plan

## Phase 1 — Kickstart

- Detect stack and repository role.
- Fill `app-profile.yaml`.
- Build `source-inventory.md`.
- Initialize indexes.
- Produce `kickstart-report.md`.

## Phase 2 — Targeted exploration

- Explore the most important features first.
- Create feature folders only where useful facts exist.
- Capture APIs, batches, integrations and data flows.

## Phase 3 — Operational knowledge

- Add known bugs, structural risks, watchlist items and root-cause playbooks.
- Link production knowledge to features and components.

## Phase 4 — Continuous enrichment

- Specs, incidents and implementation work feed the corpus through knowledge capture.
